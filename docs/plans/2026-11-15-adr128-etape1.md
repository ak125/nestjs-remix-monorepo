## Fonctionnement de la routine

- Contrôle déterministe à chaque exécution : `gh issue list` et `gh pr list` (1000 éléments au
  plus, échec si la limite est atteinte), signaux calculés par jq, empreinte SHA-256 de la file.
- Session Claude seulement si l'empreinte diffère de celle inscrite dans l'issue de pilotage et si
  le producteur du KPI du rôle 23 est présent dans le code (verrou D2, constat 3).
  CLI figé `@anthropic-ai/claude-code@2.1.316`, `--tools ""`, sans MCP, sans persistance, sortie
  JSON sous schéma, plafond `--max-budget-usd 1` par session. Authentification :
  `CLAUDE_CODE_OAUTH_TOKEN` (abonnement) ou, à défaut, `ANTHROPIC_API_KEY` ; le mode est inscrit
  dans `cout.json` (`authentification` : `abonnement` ou `cle-api`).
- Publication : propositions filtrées (issue présente dans le constat du même type, label parmi les
  24 départements, mentions `@` neutralisées), au plus 5 commentaires par exécution, sans répéter
  un commentaire déjà posé. Issue de pilotage unique, créée puis mise à jour.
- Le pilote ne ferme, ne fusionne et ne relabellise rien (D6, AI2). Le job n'a que
  `contents: read` et `issues: write`.
- Signal `mandat expiré` : non couvert avant l'étape 2 (la routine `mandat-remise` n'existe pas).

## Constats de la préparation (lecture seule, 2026-11-14 et 2026-11-15)

1. **Runner des cinq workflows `[self-hosted, Linux, X64]`.** Ils ne sont pas en attente d'un
   runner absent : l'API des jobs les montre servis par le runner `hetzner-prod` (`release-prod`
   run 43582115456, `prod-smoke-tests` run 43624210068, `deploy-monitoring-scripts`
   run 34399578062, `visual-gate` run 41236991483 ; les jobs self-hosted de `ci.yml` sont
   `skipped` sur le run 43651271674). Le tableau des constats d'ADR-128 (« ils attendent un runner
   absent ») est donc inexact ; la correction relève du vault, hors de cette PR.
2. **254 exécutions en file.** Toutes `pull_request`/`pull_request_target` de
   `automecanik-agents[bot]` sur 7 branches, créées le 2026-11-11 entre 20:20:31Z et 20:50:54Z, en
   majorité sur `ubuntu-latest` ; l'échantillon (run 43098419879) n'a aucun job. Hors de cette
   fenêtre, les exécutions se terminent normalement. Cause probable : un défaut de répartition côté
   GitHub (enregistrement de l'exécution créé, jobs jamais créés), pas un runner manquant. Incidents
   publiés : Webhooks 20:22–20:26Z
   (<https://www.githubstatus.com/incidents/1h2wbly1y72t>) ; Actions dégradé 20:48Z, résolu 21:21Z
   (<https://www.githubstatus.com/incidents/dvy0t3mvh1lg>). Corrélation partielle : l'incident
   Actions est déclaré après la création de la plupart de ces exécutions. Aucune exécution n'a été
   annulée ; leur annulation est un geste de l'owner.
3. **Tension D2 / D8, traitée par un verrou D2 dans le script.** D2 dit que la routine *agent*
   d'un rôle sans producteur de KPI ne s'active pas (conséquence d'AI1, « pas d'indicateur =
   suppression ») ; D8 active pourtant `pilote-file` (rôle 23) à l'étape 1 sans lister ce
   producteur. Voie retenue, qui n'enfreint aucune des deux : la routine s'active à la fusion
   (D8), mais sa session Claude reste suspendue tant que le producteur est absent (D2). À chaque
   exécution, `controle` lit `kpi_primary` du département 23 dans `agent-operating-map.yaml`
   (`useful_capabilities_not_complexity`) et cherche cet identifiant dans
   `backend/src/modules/admin/services/command-center-kpi.service.ts` à la version exécutée : c'est la
   définition de « présent » donnée par D2. Absent : aucune session, exécution verte, suspension
   écrite dans `cout.json` et dans l'issue de pilotage (« session Claude : suspendue »), constats
   déterministes publiés comme d'habitude. Présent : la session s'ouvre au tour suivant sans autre
   geste. Constat du 2026-11-15 : identifiant absent du fichier (0 occurrence ; `pages_generating_atc`
   et `metric_reliability` y figurent). Conséquence sur le critère « coût réel d'une journée » : tant
   que le verrou tient, il mesure le coût déterministe (0 session, 0 jeton) ; le coût d'une journée
   avec sessions se mesurera après l'arrivée du producteur. Restent à l'owner : écrire ce producteur
   (mandat séparé, sa formule est une décision métier) ou amender D8 dans le vault pour l'inscrire
   au critère de sortie de l'étape 1.
4. **Charge de la première exécution.** Exécution à blanc du 2026-11-14T23:31Z sur la file réelle :
   180 issues et 39 PR ouvertes ; 180 sans `dept:`, 172 sans mouvement depuis 7 jours, un groupe de
   titres identiques (`#1985` = `#2001` = `#2002`), 38 PR sans issue rattachée. Les premières

## Limites

- Le workflow ne tourne pas avant la fusion (geste 6).
- La voie session (appel réel à Claude, lecture de `structured_output` et de l'usage) n'a pas été
  essayée avec un vrai secret : seul le test sur fixtures la couvre, CLI simulée (un seul secret
  transmis, environnement vidé, mode d'authentification tracé).
- Secret : `ANTHROPIC_API_KEY` absent (constat de l'owner du 2026-11-15) ; `CLAUDE_CODE_OAUTH_TOKEN`
  à créer (geste 4). Le réglage fork est posé (constat de l'owner du 2026-11-15).
- Avec le jeton d'abonnement : les jetons comptés dans `cout.json` sont réels et consomment le
  quota de l'abonnement ; `total_cost_usd` est le prix équivalent calculé par la CLI, pas une
  facture. L'effet de `--max-budget-usd` sous abonnement et la durée de validité du jeton ne sont
  pas vérifiés : l'aide de la CLI 2.1.325 dit seulement « long-lived ». Un jeton expiré se voit
  comme une session en échec (exécution rouge, empreinte précédente gardée).
- Directives de durcissement systemd du runner : non essayées sur le DEV.
- Le coût réel par session n'est pas connu avant les premières exécutions.
