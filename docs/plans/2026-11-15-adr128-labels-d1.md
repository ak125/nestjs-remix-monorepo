# Labels de la file D1 (ADR-128, étape 1)

Liste versionnée des 35 labels de la file de travail : nom, couleur, description, puis la commande
`gh label create` de chacun. **Écrites, non exécutées** : la création est un geste de l’owner
(étape 1 du plan D8), avec son compte (interface web ou `gh` connecté à ce compte sur son poste ;
le `gh` du shell DEV est l’app `automecanik-agents[bot]`). Le label existant `needs-human` reste celui de l’escalade et n’est pas recréé.

## Sources des valeurs

- **Département** : `dept:NN-<slug>`, avec `business_number` et `id` de
  `.spec/00-canon/ai-registry/agent-operating-map.yaml` (24 départements) ; intitulé = son `label`.
  Le script `scripts/ops/pilote-file.sh` relit la même carte à chaque exécution.
- **Statut** : les cinq valeurs d’ADR-128 D1 (directive owner du 2026-10-23). ADR-128 renvoie
  leurs valeurs exactes au Space de pilotage, à confirmer par l’owner à l’étape 1 ; **aucune
  confirmation reçue** dans la session de préparation : ce sont donc les valeurs de D1. Les
  descriptions sont une proposition à relire avant la création.
- **Niveau** : `niveau:L0` à `niveau:L4`, échelle du skill `capability-acceptance`.
- **Remise** : `mandat-prêt` (D4). Il ne déclenche rien à l’étape 1 : la routine `mandat-remise`
  arrive à l’étape 2.

Les couleurs sont un choix de lisibilité (une teinte par famille), sans valeur métier.

## Contrôle après création

```bash
gh label list --repo ak125/nestjs-remix-monorepo --limit 300 --json name \
  --jq '[.[].name | select(test("^(dept:|statut:|niveau:|mandat-prêt$)"))] | length'   # attendu : 35
```

## Retour arrière

`gh label delete "<nom>" --repo ak125/nestjs-remix-monorepo --yes` retire un label et le détache
de toutes les issues qui le portent : à ne faire que sur un label créé par erreur.
