# Exceptions gouvernées au ratchet scripts/lint/check-definer-anon-surface.sh
#
# Une ligne = un NOM de fonction du schéma public (sans schéma ni arguments),
# précédé d'une ligne "# motif : ..." qui nomme la page servie ou la sonde CI qui
# casserait si anon perdait EXECUTE. Une entrée sans motif est refusée par le
# garde : c'est une dette, pas une exception.
#
# CRITÈRE D'ADMISSION, ET IL EST ÉTROIT
# -------------------------------------
# Une fonction n'entre ici que si elle EST le chemin de rendu d'une page publique.
# Le chemin anon n'existe que dans le container PREPROD (READ_ONLY=true, ADR-028
# Option D) : le container PROD s'authentifie en service_role et le frontend
# n'instancie aucun client supabase-js navigateur (`grep -rn '\.rpc(' frontend/app`
# = 0 occurrence). Une fonction qui ne sert AUCUNE page n'a donc jamais besoin
# d'anon, même si un contrôleur admin l'appelle : ce contrôleur tourne en
# service_role en PROD.
#
# « Aucun appelant trouvé » n'est PAS un motif d'admission — c'est un motif de
# fermeture. « Une route admin l'appelle » n'est PAS un motif d'admission — le
# garde HTTP ne protège rien sur le chemin PostgREST, qui contourne NestJS.
#
# État au 2026-09-17 : 12 entrées, établies par l'audit de l'incident
# (47 fonctions DEFINER anon-exécutables → 35 fermées par
# backend/supabase/migrations/20260917_definer_rpc_anon_lockdown.sql, 12 ici).
