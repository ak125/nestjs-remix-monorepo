## 9. Pièges qui coûtent une session entière

**`/health` reste VERT quand la base est morte.** Il ne touche pas PostgreSQL. La vraie sonde est
`curl -s http://localhost:3000/api/rm/health` et il faut **LIRE LE CORPS** : son `timestamp` est
un `now()` PostgreSQL. Idem `/health/ready` et `/api/catalog/families`.

**La sonde PROD exige un cache-buster** :
`"https://www.automecanik.com/pieces/plaquette-de-frein-402.html?_=$(date +%s)"`, attendu
`200 233894`. Sans lui on mesure du cache. Le chemin R2 dégradé rend **HTTP 200 avec
`X-Robots-Tag: noindex`** — mis en cache à l'edge et servi à Googlebot, c'est une désindexation.

**`--self-test` peut passer sur un script qui ne démarre pas** (§5.4). Tester le vrai chemin.

**Régénérer le registre : l'ordre est contre-intuitif et non négociable.**
`inventoryInputFingerprint()` empreinte `git rev-parse HEAD` → **tout commit périme le cache**.
Mais les `dist` ne sont **pas** dans l'empreinte, ce qui débloque la contradiction apparente :

```bash
npx turbo build --filter='./packages/*'   # les hooks pre-commit EXIGENT les dist
git commit …                              # d'abord le CODE / le L2
rm -rf packages/*/dist                    # la CI ne construit pas les paquets internes
npm run audit:inventory                   # APRÈS le commit : le cache empreinte HEAD
npx turbo build --filter='./packages/*'   # remettre les dist
npm run registry:heal
```

Et **`audit-reports/contract-health.json` est gitignoré** : lancer `audit:drift-dashboard` avant
`audit:cleanup-candidates` grave un `contractHealthSha256` que la CI ne peut pas reproduire.

**Régénérer depuis `/opt/automecanik/app` produit ~744 lignes de churn fantôme** (`@repo/x` →
`../dist/index.d.ts`) parce que les workspaces y sont bâtis. Il faut un clone isolé en `npm ci`
**sans build**.

**Un changement de signature de constructeur se vérifie par `grep "new <Service>("`**, pas par
une comparaison de suites de tests locales. C'est ce qui a laissé passer un `TS2554` : la suite
entière ne compilait plus, et seule la CI l'a vu.

**Un upgrade PG managé provisionne une instance NEUVE.** Tout repère de pré-vol dépendant de
l'état physique (index invalides, compteurs `pg_stat`, âge du postmaster, binaire compilé) est
**invalidé, pas violé**.

**Un `gh run list --branch main` peut renvoyer des runs vieux de six semaines.** Vérifié
aujourd'hui : le filtre de branche a renvoyé des runs d'août. Interroger le run par son ID, ou
`repos/{repo}/commits/{sha}/check-runs`.
